## 1. 全体像

CadPeta は、CAD 図面を Word / Excel / PowerPoint へ拡大しても劣化しないベクタ形式で
貼り付けるフリーソフトウェアである。PETAは範囲（全体・窓）と選択絞り込みをPDF印刷へ統一してCTB/STB反映済みの
仕上がりを提供し、PETADATAはCAD構造を保つ外部編集用SVGを提供する。

内部標準は **SVG IR**（SVG のサブセットとして定義した中間表現）である。取得側と出力側は
SVG IR だけを介して接続し、互いの実装を知らない。

```
[PETA: 全体・窓（選択絞り込み可）] CAD PDF印刷 → PDF解析 ─┐
                                              ├→ SVG IR → IR変換層 → SVG/EMF
[PETADATA: 選択] CAD DB直接取得 ───────────────┘
                                        ┌─────────┬─────────┼─────────┐
                                      EMF出力   SVG出力   PDF出力   PNG出力
                                        │
                                 クリップボード / ファイル
```

この分離が満たす性質は三つある。取得系統を追加しても出力側に手が入らない（互換CAD 対応の
追加費用が下がる。第10章に実測値）。出力形式を追加しても取得側に手が入らない（EMF 一本足を
避ける）。不具合の切り分け点が IR という一つの観測面に集約される（第9章）。

## 2. SVG IR（内部標準）

### 2.1 制約プロファイル

SVG IR は任意の SVG ではなく、許可要素を6種に限定した制約プロファイルである。
出力バックエンドが処理すべき対象を有界にすることが目的で、プロファイル外の要素は IR に
存在しない。

| 要素 | 用途 |
|---|---|
| `path` | 線分、円弧、ベジェ曲線、ハッチ輪郭、輪郭化した文字 |
| `polyline` / `polygon` | 折れ線、閉多角形 |
| `text` | 文字（フォント保持の場合） |
| `image` | 図面内ラスタ画像の位置保持（埋め込み） |
| `g` | レイヤ・ブロック単位のグループ（変換行列付き） |
| `clipPath` | ビューポート境界、ワイプアウト |

線種（破線）は `stroke-dasharray` / `stroke-dashoffset`、透明度は `stroke-opacity` /
`fill-opacity` として IR に保持し、劣化の判断は出力バックエンドに委ねる（第7章）。
グラデーション、フィルタ、アニメーション、スクリプトは許可しない。

### 2.2 座標系と単位

- ルートの `viewBox` は図形範囲（クロップ後）を表す
- `width` / `height` は mm 単位の物理寸法を持ち、貼り付け時の実寸再現の根拠となる
- Y軸は SVG 標準（下向き正）とし、CAD 座標（上向き正）からの反転は取得側の責務とする

### 2.3 出所メタデータ

PETADATAで取得した要素は `data-color-method`（aci / truecolor / bylayer / byblock）・
`data-aci`・`data-layer`・`data-entity` を保持する。PDFで取得した要素は `data-layer`
（レイヤ情報付きプロット PDF の場合）以外を持たない。プロット後の PDF には最終 RGB 値しか
残らないためで、この非対称は原理的なものである。変換層は該当メタデータの有無で処理の可否を
判定し、**系統間の機能差を分岐コードではなくメタデータの有無として表現する**。

`data-*` は通常出力では除去し、診断出力でのみ残す。直列化は SVG ライタ内の単一の関門を
通るため、除去漏れ・保持漏れが構造的に起きない。

### 2.4 生成規約（実測に基づく）

- `clip-path` は `transform` を持つ要素に直接付与しない（SVG はクリップ幾何を要素自身の
  transform で変換するため、クリップは親 `g` に置く）
- グリフ位置列を明示する `text` で先頭空白・連続空白を含む場合、`xml:space="preserve"` と
  `style="white-space:pre"` を要素に直接付す（SVG の空白正規化で位置列と文字数がずれるため）
- レイヤ別グループ化が生成する `g` には、SVG エディタがレイヤとして認識する規約属性
  `inkscape:groupmode="layer"` と `inkscape:label` を付す。名前空間宣言は適用時だけ出力し、
  未適用の出力は従来とバイト不変

### 2.5 コード上の表現

IR は `src/CadPeta.Core/Ir/IrModel.cs` に定義する。`IrDocument`（物理寸法・クリップ定義・
ノード列・レイヤグループ境界）、`IrNode` の4具象（`IrGroup`=変換行列付きグループ・
`IrPath`・`IrText`・`IrImage`）、パス幾何の `IrSegment` 4種（`IrMove` / `IrLine` /
`IrCubic` / `IrClose`）から成る。

## 3. プロジェクト構成と依存規則

実装は Clean Architecture に従い、参照（依存）の方向は外側から内側への一方向のみとする。
この規則は .NET のプロジェクト分割で物理的に強制する。

```
内核        CadPeta.Core（IR モデル・変換層。パッケージ参照ゼロ）
            CadPeta.UseCases（境界ポート所有・パイプライン合成）
取得        CadPeta.Acquire.Pdf（PETA/CLI/GUI: PdfPig）
            CadPeta.Acquire.{Acad, Ares, Ijcad, Bricscad}（PETADATA: 各 CAD API）
            CadPeta.Acquire.Common（アダプタ間共有の計算層。Core のみ参照）
グリフ      CadPeta.Glyphs.Shx（自前 SHX 解釈器。パッケージ参照・P/Invoke ゼロ）
出力        CadPeta.Out.{Emf, Pdf, Png}
合成ルート  CadPeta.Plugin.{Acad, Ares, Ijcad, Bricscad}、CadPeta.Cli
```

- 取得系（Acquire.*）と出力系（Out.*）は互いを参照しない
- CAD 製品固有アセンブリは対応する取得アダプタと合成ルートにだけ現れ、すべてコンパイル
  専用参照とする（実行資産に含めない。実行時はホスト CAD が同名アセンブリを提供する）
- 実行時のサードパーティ依存は PdfPig（Apache-2.0）と System.Drawing.Common・
  System.Text.Json（MIT）のみ。強いコピーレフト・有償 SDK には依存しない
- 参照方向は tests/ の ArchitectureTests（17件）が機械検査する。アセンブリ参照メタデータで
  「内核は外部参照を持たない」「取得と出力は相互参照しない」等を、メソッド属性の走査で
  「内核・ユースケース層・SHX 解釈器・PDF 出力は P/Invoke を持たない」を検査する

### 3.1 境界ポート

ユースケース層が3つの境界ポートを所有する（`src/CadPeta.UseCases/Ports.cs`）。

| ポート | シグネチャ | 役割 |
|---|---|---|
| `IIrAcquirer` | `IrDocument Acquire(string sourcePath, IrDiagnostics diag)` | 取得: 入力から SVG IR を得る |
| `IIrOutput` | `void Write(IrDocument ir, string outputPath, IrDiagnostics diag)` | 出力: SVG IR をファイルへ書く |
| `IGlyphOutliner` | `List<IrSegment>? Outline(GlyphRun run)` | 文字ランをグリフ輪郭へ展開する |

アダプタがポートを実装し、合成ルート（プラグイン・CLI）だけが結線する。

### 3.2 TFM（ターゲットフレームワーク）戦略

TFM（Target Framework Moniker）は .NET のターゲットフレームワーク識別子で、
`net48` / `net8.0-windows` / `net10.0-windows` がこれに当たる。プラグインはホスト CAD の
ランタイムで読み込まれるため、実行基盤を3系で揃える（AutoCAD 2024 以前 = .NET Framework 4.8、
2025/2026 = .NET 8、2027 = .NET 10）。

- 内核（Core・UseCases）と Glyphs.Shx・Out.Pdf・Acquire.Common: `netstandard2.0`
  （3系すべてから参照可能な中立ターゲット）
- AutoCAD 系アダプタと Out.Emf・Out.Png・Acquire.Pdf: `net48` / `net8.0-windows` /
  `net10.0-windows` の3系マルチターゲット
- 互換CAD アダプタ: 各ホストのランタイムに合わせた TFM。ARES は
  `net48`（ARES Standard 2020／2023／2024＝.NET Framework 4.8 世代）／`net8.0-windows`
  （ARES Standard 2027＝.NET 8 世代）の2系マルチターゲット。IJCAD・BricsCAD は対応版が
  .NET 8 世代のみのため `net8.0-windows` 単一
- CLI: `net10.0-windows`

TFM とパッケージ版数は `src/Directory.Build.props` に一元定義し、csproj へ直書きしない。

### 3.3 ARES の版とSDKアセンブリ名

ARES は net48 世代でも、SDKのアセンブリ名が版ごとに異なる。
名前空間は全世代で共通（`Teigha.*` と `FxCoreMgd` 側の `Teigha.ApplicationServices` 等）だが、
参照するDLLの版サフィックスが違うため、同じ net48 でも版ごとに正しいDLLを参照して組む必要がある。

| ARES 版 | ホストランタイム | SDKアセンブリ名 | ProgID（COM API 版） |
|---|---|---|---|
| 2020 | .NET Framework 4.8 | `TD_Mgd_4.03_14.dll` / `FxCoreMgd_4.03_14.dll` | `PCAD_AC_X.AcadApplication.4.4` |
| 2023 | .NET Framework 4.8 | `TD_Mgd_4.03_15.dll` / `FxCoreMgd_4.03_15.dll` | `PCAD_AC_X.AcadApplication.4.6` |
| 2024 | .NET Framework 4.8 | `TD_Mgd_23.1_16.dll` / `FxCoreMgd_23.1_16.dll` | `PCAD_AC_X.AcadApplication.23.1` |
| 2027 | .NET 8 | `TD_Mgd_Net8_26.8_17.dll` / `FxCoreMgd_Net8_26.8_17.dll` | `PCAD_AC_X.AcadApplication.26.8` |

net48 のどの版を参照するかは `AresSdkYearNet48`（既定は 2024）で選ぶ。
配布ハーネスは 2020／2023 を `-p:AresSdkYearNet48=<年>` で個別に組み、`ares\<年>` フォルダへ分けて収める。
版とDLLサフィックスの対応表、および参照DLLの解決先は `src/Directory.Build.props` が持つ。
未対応の年式を指定すると、参照解決の手前で明示エラーになる。

`CadHostLanguage` は表示言語の判定に `HostApplicationServices.Current.RegistryProductRootKey` を使う。
ARES 2020 のSDKには `UserRegistryProductRootKey` が無く、`RegistryProductRootKey` は対応する全世代のSDKにあるためこちらを使う。

## 4. PETADATA（CAD DB直接取得による構造SVG）

CAD 内の独立コマンドとして、選択オブジェクトを図面データベースから直接 IR へ写像する。
プロットを経ないため色・線幅は図面の表示のまま（プロットスタイル非反映）で、その代わり
取得単位（選択オブジェクト）と意味情報（文字・レイヤ・元の色）を保つ。PETAからは呼ばれない。

主要エンティティの写像:

| CAD エンティティ | IR 表現 |
|---|---|
| 線分、ポリライン | `polyline` / `path` |
| 円、円弧、楕円 | `path`（楕円弧はベジェ展開） |
| スプライン | `path`（3次非有理クランプはノット挿入による厳密ベジェ変換。それ以外は許容誤差〔既定 0.01mm〕の折れ線近似＋処理ログ） |
| 文字（TrueType） | `text`（フォント保持） |
| 文字（SHX・ビッグフォント） | `path`（自前解釈器による輪郭化が既定。第8章。設定で代替書体の `text` へ切替＋処理ログ） |
| ハッチ | `path`（塗りまたはパターン線の展開） |
| ワイプアウト | 背景色 `polygon`（白塗り）。`clipPath` 表現は採らない（Office の「図形に変換」がクリップを破棄する実測による） |
| ブロック参照 | 変換行列付き `g` に展開 |
| 寸法 | 構成要素（線・矢印・文字）へ分解して上記に帰着 |
| MTEXT | `text` 列＋背景マスク（「図面の背景色を使用」は白塗り＋診断ログ） |
| 複雑線種の記号 | SHX 解釈でジオメトリへ展開（後述） |

色の解決: ByLayer / ByBlock は取得時に実効値へ解決し、解決前の指定方法を
`data-color-method` に記録する。ACI と TrueColor の区別は CAD API の色種別判定に基づき、
推測を含まない。

### 4.1 破線の端部整列

CAD の実描画は破線パターンを機械的に敷かず、端部を整列する。実測から導出した次の規則を
取得時に再現して `stroke-dasharray` を生成する。

- **開いた曲線**: パターン周期 P に対し n=floor(L/P) 周期を敷き、余り ρ=L−nP を
  先頭の実線要素だけの両端片へ折半する（両端が実線片で始まり終わる）
- **閉じた曲線**: n=round(C/P)（最近接整数）周期へ全要素を一様伸縮する

この規則は直線・円・記号の計39ケースの実測と代数一致 ±0.03mm で確認しており、導入により
PETAのプロット描画との突き合わせ異画素率は 2.39% から 0.35% に減った。

### 4.2 複雑線種の記号

線種定義に含まれる記号（シェイプ・文字）は、SHX 解釈器（第8章）でジオメトリへ展開し、
曲線沿いの出現位置ごとに `path` / `text` として配置する。破線パターン自体は
`stroke-dasharray` のまま、端部整列後の位置へ記号と一体で調整する。展開は処理ログに
記録する。実測で確定した意味論: 記号の基準点は「記号を運ぶダッシュ要素の終端」、
線種定義の S= はシェイプ設計単位への直接倍率である。

## 5. PETA（PDF印刷単一経路）

CAD のプロットエンジンでベクタ PDF を生成させ、その PDF を解析して IR へ写像する。
プロットスタイルは PDF 生成時点で CAD 側が適用済みのため、CadPeta は CTB/STB の解釈を
再実装しない。プラグインは範囲（全体・窓）を必ず確定してプロットし、すべてここへ合流する。

- **全体・窓**: 対象レイアウトをサイレントプロットする。窓はWindowへ写し、余白帯をクロップする
- **選択絞り込み**: オブジェクト選択（先選択またはO）は範囲内の出力対象を選択オブジェクトだけに絞る。
  通常図形はWblockで側DBへ複製し、元レイアウトのページ設定を引き継いだ側DBレイアウトを同じ範囲規則で印刷する。
  通常Viewportを含む場合は元レイアウトを未確定トランザクション内で一時隔離し、Viewport固有の表示設定を保持したまま印刷する。
  非印刷レイヤから一時退避するのは直接選択した非Viewport図形だけであり、Viewport内のモデル図形は強制表示しない。
  未対応図形は既定中止・明示確認とする
- **単独入口**: 生成元を問わない任意のベクタ PDF を直接受け付ける。CAD のインストールを
  前提とせず、プラグイン未対応 CAD の受け皿となる

解析は PdfPig（Apache-2.0）を用い、PdfPig が公開しない3点（透過α・レイヤ帰属・線幅の
CTM 補正）は約100行の内容ストリーム状態追跡で補完する。解析結果は PDFBox を正解データ
生成器とした照合で、3PDF・10,728 オブジェクトの全件一致（許容: 座標 0.01pt・色 2/1000・
α 1e-4・線幅 0.001pt）を確認している。

写像規則の要点:

- パスはベジェ制御点を保持し、色は最終 RGB、線幅は CTM スケール補正後の mm 値とする
- 文字はテキスト表示オペレータ単位のランとし、グリフごとの位置列で字送りを固定する。
  幅係数（Tz）は `scale`、回転はベースライン方向から求めた `rotate` で `transform` に写す
- 線幅0（デバイス最細線）は SVG に対応概念がないため固定幅へ置換し、診断ログに記録する
- レイヤ（OCG）は要素単位の `data-layer` に写す（z順保存と両立させるため `g` を使わない）
- 描画順は内容ストリーム順を保存する（ワイプアウト=白塗りの成立条件）
- 回転ページ（/Rotate）は四半回転を画像画素へ無劣化で焼き込む
- ページの /Resources はページ辞書から親 Pages ノードへ遡って継承解決する（ODA 系 CAD の
  PDF は ExtGState・レイヤ Properties を親ノードに置くことがあり、これを取り落とすと
  透過・レイヤ情報が消える）
- 用紙全面を覆う背景矩形は「描画順が最初期・ページ範囲とほぼ一致・塗りのみ」の三条件で
  同定し既定で除去する。AutoCAD 標準 PDF ドライバの実測では背景矩形は出現せず、
  他ドライバ由来 PDF への防御として維持している

## 6. IR 変換層

IR を受け取り IR を返す変換の直列合成である。適用順は固定で、パイプライン
（`ConvertPipeline`）が次の順に列挙する。

1. **背景除去**（PDF由来の IR のみ対象）
2. **クロップ**: 範囲外要素の保守的間引き（ストローク半幅・文字クアッドを考慮した bbox
   判定）、`viewBox` と物理寸法の更新、余白の付与
3. **色変換**（モノクロ化・グレースケール化・色の一括置換）
4. **文字アウトライン化**（オプション。グリフ輪郭ポートで `text`→`path` の 1:1 置換）
5. **レイヤ別グループ化**（オプション。構造変換のため最後）

色変換の規則:

- モノクロ化: 純白（8bit 量子化後 255,255,255）の stroke / fill は維持し、他は黒
  （紙面の白を保つ）
- グレースケール化: Gray = 0.3R + 0.59G + 0.11B（ISO 32000-1:2008 §10.4.2 の
  RGB→DeviceGray 変換式）
- 色置換: 8bit 量子化等値で一致判定し、複数規則は指定順の最初の一致のみ（連鎖しない）。
  モード変換（モノクロ・グレー）より先に適用する
- 画像（`image`）は色変換の対象外とし、除外した事実を診断ログへ記録する

レイヤ別グループ化は `data-layer` によるレイヤ初出順の `g` 再グループである。z順（描画順）の
保存と両立しないため既定オフとし、適用時はレイヤ数と移動要素数を処理ログへ記録する
（実物図面の実測例: 41 レイヤ・移動 45,607/70,574 要素、グループ化前後の描画差は
異画素率 0.1759%）。

## 7. 出力バックエンド

### 7.1 EMF

Office 貼り付けの主形式。クラシック GDI レコードを P/Invoke で直書きする（EMF+ は
使わない）。この方式は Office の「図形に変換」（分解編集）互換の実測比較で選ばれた:
EMF+ Only は分解不能（図形数1・テキスト回収0件）、EMF+ Dual は分解できるが文字が細切れ
（4分割）でファイル約3.7倍、クラシックは文字列単位のテキスト図形へ完全分解しフォント名を
保持する。

Office の変換仕様に合わせた生成規約（いずれも実測に基づく）:

- **事前クリップ**: Office の図形変換はクリップレコードを破棄し、隠していた線が再出現する。
  このため IR の `clipPath` は EMF 生成時にジオメトリへ適用してから出力する（線=
  Liang-Barsky、塗り=Sutherland-Hodgman、交差ベジェは折れ線化、交差文字は輪郭化。
  すべて診断ログ付き）
- **絶対座標レコード規約**: 図形変換は現在位置依存のレコードを正しく処理せず、線の終点が
  飛んで図形が崩壊する。パスブラケット外の描画は始点込み絶対座標レコード（POLYLINE16 /
  POLYBEZIER16 等）のみで書き、MOVETOEX＋"To"系レコードと SETWINDOWORGEX による原点移動を
  使わない
- **96dpi 固定**: Office の貼り付けサイズ計算は記録デバイスの実解像度を無視して 96dpi を
  仮定する（実画面 108.9dpi の参照 DC で記録すると一様に +13.5% で貼り付く実測）。記録は
  論理単位 0.01mm の MM_ANISOTROPIC とし、viewport とヘッダ szl を 96dpi 固定で書く。
  ヘッダ rclBounds / rclFrame に IR の物理寸法から算出した値を設定し、実寸貼付を実現する
- **破線のセグメント展開**: 破線幾何ペンは Office の図形変換を全面的に壊すため、破線は
  実線セグメント列へ展開して出力する
- **透過の劣化**: 白背景と事前合成した不透明色へ近似し、件数を処理ログに記録する
- **画像**: STRETCHDIBITS の無圧縮 24bpp BGR DIB で出力する（透過は合成済みでアルファ
  バイト不要。32bpp 比で約25%減。行は DWORD 境界へパディング）
- **文字**: TrueType フォント保持（既定。貼り付け先で編集可）と輪郭化（環境非依存の見た目）
  の二方式を設定で選べる

### 7.2 SVG

IR は SVG の制約プロファイルであるため、出力はほぼ直列化のみである。透明度を含む全属性を
無劣化で保持する。`data-*` は既定で除去し、診断用出力でのみ残す。

### 7.3 PDF

自前の最小ライタである（依存パッケージ追加ゼロ・P/Invoke ゼロ）。クラシック xref・
無圧縮ストリームで書き、同一 IR から3系 TFM すべてでバイト決定的な PDF を生成する。
破線（d 配列）・透過（ExtGState の ca/CA）・クリップ（W / W* n）は PDF ネイティブ表現で
無劣化。文字はグリフ輪郭ポートで輪郭化する（フォント埋め込みなし。輪郭化は処理ログへ記録）。
画像は PNG を純マネージドでデコードし、無圧縮 RGB＋SMask（アルファ）で埋め込む。

### 7.4 PNG

GDI+ による直接ラスタライズである。既定 150dpi・指定可。表示互換の確認用。

### 7.5 クリップボード

EMF を `CF_ENHMETAFILE` でクリップボードへ登録する。登録処理内で読み戻しバイト一致の
自己検証を行う。SVG には Office 間で通用する標準クリップボード形式がないため、SVG は
ファイル出力のみとする。

## 8. グリフ輪郭（IGlyphOutliner と自前 SHX 解釈器）

文字の輪郭化はグリフ輪郭ポート `IGlyphOutliner` に集約する。輪郭はテキスト空間
（原点=ベースライン左端・単位 mm・幅係数未適用）で返し、取れない場合は null を返して
呼び出し側が代替（フォント保持等）へフォールバックし、その事実を診断ログへ記録する。
実装は2つある。

- **GdiGlyphOutliner**（Out.Emf）: TrueType。GDI のパスブラケットで輪郭を取る
- **ShxGlyphOutliner**（Glyphs.Shx）: SHX。自前解釈器による輪郭化

`CadPeta.Glyphs.Shx` はパッケージ参照ゼロ・P/Invoke ゼロ・netstandard2.0 の自前 SHX
解釈器で、SHX の3形式（unifont・bigfont・shapes）をバイナリ解析する。バイトコード命令は
0〜14 を実装し、円弧はベジェへ展開する。実フォントファイルの全 28,269 グリフの走査で
エラーゼロ、AutoCAD 実機レンダとの字形機械比較で全行閾値内（異画素率 0.246%）を確認して
いる。命令11（フラクショナル弧）は実データに一度も出現せず、実装の信頼度が低いことを
コード内に明記している。

ビッグフォントの文字コード変換（Unicode→CP932）は 9,274 エントリの埋め込み表で行う。
実行系の `Encoding.GetEncoding(932)` は net48（OS の NLS）と .NET 8/10（CodePages
パッケージ）で実装が異なり縁の写像が食い違い得るため、埋め込み表により3系 TFM・ホスト
環境に依らないバイト決定性を確保する。

複雑線種の記号輪郭も同じ解釈器が担う（記号用は above 正規化を持たず、シェイプ設計単位の
まま返す）。

## 9. 診断設計

不具合の切り分け点を IR という観測面に集約する。

- **プラグインの診断コマンド `PETADIAG`**: `PETA` のデバッグ用で、プロンプトとオプションは
  `PETA` と同一。ただし記録ファイルを図面フォルダへ残すことが目的のため、`ファイル出力(F): オフ`
  を指定しても無視し常に一式を書き出す（`PetaRunner.Run` の `effectiveFileOutput = choice.FileOutput
  || diagnostic`）。オフ指定時は「診断モードのためファイル出力オフ指定を無視し一式を書き出す」と
  表示する。通常運用の `PETA` は利用者向けであり、`PETADIAG` は利用者向け導線・コマンドリファレンス
  には出さない
- **プラグインの診断コマンド `PETADATADIAG`**: `PETADATA`（構造SVG書き出し）のデバッグ用で、
  プロンプトとオプションは `PETADATA` と同一。書き出し先フォルダへ各段ダンプと diag.json を残す
- **各段ダンプ**: 診断モード（CLI `--diag` / プラグイン `PETADIAG`・`PETADATADIAG`）は変換層の各段の
  前後で IR を SVG ファイルとしてダンプする。命名は `<base>.stageNN.<段名>.svg`。
  段0=取得直後、以降は各段の適用後（N 段の変換に対し N+1 ダンプ）。ダンプはそのまま
  ブラウザで開けるため専用ビューアを要しない
- **非可逆処理ログ**: 透過の劣化・SHX 輪郭化・クリップ交差文字の輪郭化・線幅0の置換・
  クロップ間引き・代替書体・記号展開といった非可逆処理は、診断モードの処理ログ
  （diag.json）へ件数と対象を記録する
- **出所メタデータの関門**: `data-*` は通常出力から除去し診断出力でのみ保持する（第2.3節）

これにより、IR ダンプの提出だけで「取得・変換・出力のどこで壊れたか」を切り分けられる。

## 10. 拡張点と差し替え費用の実測

拡張点は3ポート（`IIrAcquirer`・`IIrOutput`・`IGlyphOutliner`）であり、結線は合成ルート
（プラグイン・CLI）だけが行う。差し替え・追加の費用は互換CAD 3製品（ARES・IJCAD・
BricsCAD）の実装で実測されている。

- 内核・境界ポートは無改変。取得アダプタ3ファイル（計 1,787 行）の移植で、API 差異に
  起因する実質ロジック変更は0行（名前空間置換とクラス名リネームが主体）
- 共有層（Acquire.Common 765 行・Glyphs.Shx 1,328 行・Out.Emf 1,264 行ほか計約 5,000 行）は
  変更ゼロで再利用
- 3製品に共通する唯一の API 欠落は `LinetypeTableRecord.ShapeIsUprightAt`（複雑線種記号の
  正立判定）で、互換ヘルパ1点で吸収
- 出力品質の同等性: EMF の実寸情報（rclFrame）は3製品で AutoCAD とバイト同値。レンダ比較の
  異画素率は ARES 0.002%・IJCAD 0.00723%・BricsCAD 0.04243%

出力形式の追加（PDF・PNG）とグリフ輪郭の差し替え（GDI→自前 SHX 解釈器）も、同様に内核・
ポート無改変で成立した。

## 11. 検証の型

品質は主に次の型で担保している。

- **バイト回帰**: 変更前に既存出力（SVG・EMF、診断モードのdiag.json）を採取し、変更後にバイト比較する。
  決定的出力（SVG 直列化・EMF 直書き・無圧縮 PDF）がこの検証を可能にしている
- **機械比較＋可視再現＋目視の3点判定**: 描画系の判定は集計値ではなく描画結果で行う
  （正解レンダラとの画素差分・可視アプリでの再現・目視）
- **PETADATA/PETA 突き合わせ**: 同一図面を構造書き出しと印刷で取得して画素比較する。構造差（幾何・色・z順・
  破線・ハッチ・ワイプアウト・ブロック・寸法）ゼロ、全体異画素率 0.640%、残差はフォント
  描画差等の特定済み3類型
- **Office E2E**: 実寸（誤差 ±0.11mm 級）・図形分解数・文字回収数・書換一致を Excel /
  PowerPoint の自動化で確認する
- **実行基盤マトリクス**: 3系 TFM×実機 CAD で成果物のバイト一致を確認する（例: AutoCAD
  2027〔.NET 10〕と 2026〔.NET 8〕の全成果物バイト一致）

## 12. グラデーションのラスタ正規化

CAD各社のHatch APIから得た形状名、色ストップ、角度、ShiftをCAD非依存DTOへ移し、
`CadPeta.Acquire.Raster`が最終文書座標の画素中心を局所座標へ逆変換して`t(x,y)`を評価する。
9形状の式はAutoCAD純正プロットの黒白チャート（輝度=`t×255`）から導出した。境界3mmを除く
固定格子をCIへ埋め込み、JPEGノイズを含む実測許容値で回帰する。

境界内判定は偶奇則でアルファへ焼き込み、色はsRGB 8bitで補間する。要求DPIを無条件に確保せず、
辺長・1画像画素数・文書総画素数の名前付き上限から実DPIを決めるため、巨大図面でも決定的に動作する。
式未対応名や逆行列を作れない変換だけが代表色フォールバックとなる。

EMFではアルファを既定白または指定背景色と事前合成する。背景色はpath/text/imageの全経路で共通で、
色と非可逆処理件数を診断へ記録する。

## 13. 表示文言の言語カタログ（lang ファイル）

プラグインのコマンドライン表示文言は、言語カタログ経由で日本語（ja）と英語（en）を出し分ける。
実装は2層に分かれる。カタログ本体 `MessageCatalog` と、保管・読込・現在値（実行コンテキスト
単位の ambient 値）を持つ `MessageCatalogs` は `CadPeta.UseCases` にあり、BCL だけで完結する。
言語解決 `Msg`（`CadPeta.Plugin.Shared`）は「このホストはどの言語で動いているか」の判定と
コマンド開始時の初期化を担い、プラグイン層の全表示がカタログを通る。結果サマリ等の文言
（`RunSummary`・`PetaOutcome`）はプラグインが選択済みカタログを引数で渡し、クリップボード層
（`EmfClipboard`）・一時成果物層（`ArtifactScope`・`ArtifactRecovery`）・ビルド識別子
（`BuildStamp`）と取得層（`Acquire.*`）の利用者向けログは ambient の現在カタログ
（`MessageCatalogs.Current`）を引く（診断カテゴリは言語不変のまま）。読込フック
（NETLOAD 時のバナー）はコマンドスコープ外の一度きりの表示で、カタログと書式フォールバックの
報告先をその場で解決して使う。

CAD 不要の合成ルート（CLI・GUI が使う `PdfPetaPipeline`）は言語切替を提供せず、常に既定の
ja で表示する。共有層（取得・クリップボード）の文言はこのルートでもカタログを通るため、
差し替え lang ファイルの異常（読込不能・キー欠落・表示時の書式フォールバック）の報告は
CAD 殻と同様に実行ログへ結線する。lang ファイルの不在は報告しない（言語切替を提供しない
実行形態では、単一ファイル配布を含め常態のため）。

### 13.1 ファイル形式と探索順

カタログは LCID 名の平文ファイル `1041.lang`（ja）/ `1033.lang`（en）で、原本は
`src/CadPeta.UseCases/lang/` にある。1行が `キー=値`（UTF-8）で、空行と `#` 行は無視する。
値は .NET の複合書式（`{0}`、`{1:N0}` 等）で、数値は InvariantCulture で整形する
（表示の数値表記を実行環境の地域設定で揺らさないため）。エスケープは `\n`（改行）、
`\t`（タブ）、`\s`（空白。行末の空白をエディタに落とされないための明示表記）、`\\` の4種とする。

実行時は CadPeta.UseCases.dll の隣の lang フォルダ（`lang\1041.lang` 等）を先に読み、無い・読めない
場合は同じ内容の組み込みリソースを使う。外部ファイル方式のため、文言の差し替えと言語の追加に
再ビルドを要しない。
不正な行・重複キー・未知のエスケープ・不正な複合書式は行を黙って捨てず、ファイル全体を
不読として組み込みへ切り替え、理由をコマンドラインへ報告する。複合書式は Format を初めて
呼ぶ時点（コマンド実行中）ではなく読込時に検証し、対象は中括弧の構文（閉じていない `{` 等）と、
同キーの組み込み定義に無い引数番号の使用である。引数の型に依存する書式不正（数値への未知の
書式指定等）は読込時に判定できないため、表示時にそのキーだけ組み込みの文言へ切り替えて続行
し、切り替えの都度、失敗したカタログ・キー・理由をコマンドラインへ報告する
（コマンドを中断させない・黙って切り替えない）。この報告自体が失敗した場合（ログ書き込み
不能等）も表示の継続を妨げず、理由は Trace へ退避する。報告先はコマンド開始時に結線し、
コマンドの終了で解除する（ログ経由のエディタ参照をコマンドの寿命を超えて保持しない）。
言語の選択と報告先は、静的な共有値ではなく実行コンテキスト（コマンドの実行の流れ）単位の
状態として持つ。報告はその流れの報告先だけへ届き、コマンド文脈が入れ子・並行に重なっても、
言語選択の上書き・診断の相互配送・解除後の遅延書き込みが起きない。スコープの終了は
直前の状態への復元で、未初期化の文脈の既定は ja とする。値は引数の有無に依らず複合書式として展開する（`{{` は `{`
として表示される）。

### 13.2 言語の解決

言語の判定材料はホスト依存のため、各殻が確度の高い順にヒント列を集め
（`CadHostLanguage.Hints()`、4製品共通）、写像は `Msg.ChooseLcid` に一本化する。

1. 環境変数 `CADPETA_LANG`（明示指定。ホスト CAD の言語と独立に切り替える口）
2. システム変数 `LOCALE`（AutoCAD 系の言語コード。日本語版 AutoCAD 2026 の実値は `JA`）
3. 製品登録レジストリキーのパス（AutoCAD 系は末尾に `:411` のような LCID の16進を含む）
4. プロセスの `CurrentUICulture`

各ヒントは二文字の言語ファミリ（`ja`/`jpn`/`jp`、`en`/`enu`/`eng`。大文字小文字不問）か、
末尾 `:LCID` のプライマリ言語 ID で写像し、最初に写像できたものが勝つ。全滅は en（1033）とし、
判定不能だった旨をコマンドラインへ報告する。差し替えた外部ファイルにキーが無い場合は、
同言語の組み込みカタログ、ja はさらに en の文言で補い、補ったキーの一覧も報告する
（黙って落とさない）。殻の初期化を通らない経路（単体テスト等）の既定は ja で、従来文言と
一致する。

### 13.3 言語不変の要素

コマンド名、キーワードのグローバル名（`All` 等）と短縮名（`A` 等）、確認プロンプトの応答
（`Y`/`Yes`）、診断カテゴリ文字列（`AcquireDiagCategories` 等）と diag.json の内容は翻訳しない。
スクリプト・自動化・機械比較が言語で割れないための固定である。診断カテゴリはコンソールにも
そのまま表示されるが、行の書式（`{種別}: {件数}件`）だけを翻訳する。例外説明の枠
（`PetaCommand.Describe` 等）は翻訳し、内挿される `ex.Message`・`ErrorStatus` は実行環境の
原文のまま残す。下位層が throw する内部不変条件のメッセージ（正常運用で利用者に出ない類）と、
Trace へ退避する開発者向け文言（コマンドライン出力の打ち切り通知など）は日本語のままとし、
対象外の割り切りをここに記す。

### 13.4 検証

ja / en のキー集合一致、言語ファミリ写像、未対応言語（fr 等）の en フォールバック、lang 形式の
パーサは単体テスト（`MsgCatalogTests`）で固定する。ja の実機挙動は選択絞り込み回帰
（`selection_plot_matrix.ps1`、accoreconsole `/l ja-JP`）が従来文言の照合で保証し、en は
`CADPETA_LANG=en` の accoreconsole 実行で確認する。配布4種 ZIP への lang ファイル収録は
`dist/build_dist.ps1` が必須検査する。

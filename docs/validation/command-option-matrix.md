# コマンドオプションの全組み合わせ検証

PETA と PETADATA の対話オプションを全因子で実機駆動し、成果物と表示文言を機械判定した結果を記す。
再実行ハーネスは `tests/tools/regression/peta_option_matrix.ps1` ほか（手順は `tests/tools/README.md`）、
検証日は 2026-07-17〜18、キャンペーン記録（実行時 HEAD・差分・untracked の SHA256）は成果物側の campaign.json にある。
内容フラグと golden は 2026-07-17 のビルドで採取して凍結し、最終確認は回転フィット尺度の是正・
CCITT 画像対応・取得アダプタの共有ソース統合を合流した HEAD で全群を再実行して行った
（凍結 golden・クロスチェックとも全一致。統合後の無回帰をこの一致が固定する）。

## 対象と環境

- AutoCAD 2026 accoreconsole：全因子マトリクスの本体。
- AutoCAD 2027 accoreconsole：版差スモーク固定12件。
- ARES 2027、IJCAD 2026、BricsCAD V26（GUI COM 駆動）：各2件のオプションスモークと、用紙・回転回帰。
- 入力図面：`TESTCHART2.dwg`（モデル）、`TESTCHART2_layout.dwg`（PETA_A3・A3 1:1）、`gradient/gradient_e2e.dwg`。

## 判定と結果

全群で次の件数を実行し、すべて合格した。

| 群 | 内容 | 件数 |
|---|---|---|
| ビルドと単体テスト | 4製品ビルド警告0、xUnit 420/424（net8/net10） | 2 |
| 既存E2E | selection 11、crop 3、窓UCS回帰 7、窓フィット尺度 5、透過 5、plugin matrix 8 | 39 |
| PETA 全因子 | 空間×範囲×絞り込み×余白×レイヤ×文字輪郭×ファイル出力×EMF背景 = 2^8（AutoCAD 2026） | 256 |
| PETA エッジ | A=Enter一致、縮退窓、EMF背景不正入力、Enter維持、トグル偶奇、絞り込み解除、先選択 | 10 |
| PETADATA 全因子 | 尺度×余白×レイヤ×文字輪郭×SHX代替 = 2^5、グラデーションDPI 2、空選択 1 | 35 |
| 診断スモーク | PETADIAG、PETADATADIAG（diag.json・stageダンプ・ファイル出力強制） | 2 |
| AutoCAD 2027 | 固定12件（判定は 2026 と同一定義） | 12 |
| 三点検証 | ネイティブ -PLOT 独立オラクルとの機械比較・可視再現・目視（代表8件） | 8 |
| 互換CADスモーク | ARES 2027・IJCAD 2026・BricsCAD V26 ×（レイヤ+文字輪郭の全体、余白5の窓） | 6 |
| 用紙・回転回帰 | Acad2026・Ijcad2026・BricscadV26 × PlotRotation 0/90/180/270 | 12 |

ケース単体の判定に加え、ケース間のクロスチェック（PETA 396件、エッジ 10件、PETADATA 26件、2027 9件）を行い、すべて一致した。

- EMF背景（B）だけ違う対は SVG が SHA256 一致し、透過要素を含むモデル空間では EMF が不一致になる（B は EMF の不透明化だけに作用する設計の固定）。
- ファイル出力（F）だけ違う対は、オフ側のクリップボード読み戻し EMF とオン側の EMF ファイルがバイト一致する。
- レイヤ（L）だけ違う対は描画要素数（path・text・image）と寸法が不変で、グループ化が並べ替えのみであることを固定する。
- モデル空間は（範囲・絞り込み・余白）が同じ組で寸法が一致し、窓の余白は「余白0の寸法＋四辺5mm」の算術に一致する。
- レイアウトの窓は既知正解（窓 100×70／viewBox `160 113.5 100 70`、余白5で 110×80／`155 108.5 110 80`）と厳密一致する。

三点検証は、同じ2点を CAD ネイティブ `-PLOT` へ与えた PDF を独立の正解とし、
PETA の PDF、EMF（GDI 描画）、SVG（Chromium 描画）を 300dpi で前景 bbox・recall・precision・IoU により照合した
（シフト許容 0.2mm、判定器は空画像・図形欠落・0.3mm平行移動・誤色の負例が全て失敗することを単体試験で確認済み）。
EMF 合成下地色は、透過50%セルの実測色が `round(元色×0.5＋下地×0.5)` に一致することを #FFFFFF と #FF8040 の両下地で確認した。
併せて8件の並置画像を目視し、範囲・欠落・クリップ・文字・レイヤ・背景合成・寸法に差異がないことを確認した。

## CLI（cadpeta.exe）の結線と他所産 PDF

CAD 側と共有されない層は `tests/tools/regression/cli_option_matrix.ps1` で検証し、全件合格した（2026-07-18）。

| 群 | 内容 | 件数 |
|---|---|---|
| 結線の全因子 | keepBg×色（なし・mono・gray・置換）×レイヤ×文字輪郭×クロップ×EMF背景（出力は SVG+EMF+PDF+PNG 固定） | 256 |
| 付帯 | クリップボード既定動作、--png-dpi、--diag 段階ダンプ、keepBg 実効（背景矩形フィクスチャ）、置換×mono/gray の適用順 | 6 |
| エラー経路 | 排他・依存・不明オプション・不正色・入力不在の非0終了と文言 | 7 |
| 他所産 PDF | 合成フィクスチャ4種（CCITT 1bit 含む）、実物図面、Word、Excel、Edge 印刷の既定変換と入力レンダ照合 | 8 |

この検証で PDF 書き出しの PNG デコーダがビット深度1・2・4（グレー・パレット）を受けられず、
CCITT 由来の 1bit Indexed 画像を含む入力の `--pdf` 出力が未処理例外で失敗する欠陥を検出し、是正した
（デコーダのサブバイト展開対応と、CLI プロセス境界での例外全文報告。単体テスト2件で固定）。

Chromium 印刷 PDF は Type3 フォントを使い、フォント名では実体を解決できない。変換は
「フォント名を解決できず」「フォント代替」を診断へ記録して代替書体で継続し、字形差の分だけ
入力レンダとの recall が下がる（実測 0.93。SVG 出力は文字要素を保持するため一致する）。
これは対象（CAD 産ベクタ PDF）外の入力に対する診断つきの縮退であり、ハーネスは診断記録の実在を
必須にした上で回帰床 recall 0.90 で判定する。

## 実測で確定した事実

- accoreconsole のスクリプト座標入力は、2点目（GetCorner・-PLOT の右上コーナー）が定常オブジェクトスナップで近傍ジオメトリへ吸着する。
  ネイティブ -PLOT がページ設定へ格納する窓（DXF 140/141）も同値になるため、製品でなく入力経路の性質である。
  座標を入力するハーネスは OSMODE を保存→0→復元して回避する。
- `TESTCHART2_layout.dwg` のページ設定は透過を印刷しないため、EMF背景（B）の効果はモデル空間の出力にだけ現れる。
- IJCAD 2026 の PDF ドライバはレイヤ情報（OCG）を埋め込まず、レイヤ別グループ化は警告付き縮退（グループ化なしで出力続行）になる。
  BricsCAD V26 と AutoCAD は OCG を埋め込み、グループ化される。
- PETADATA の書き出し範囲は線幅の半分を含む保守的 bbox で、線幅は出力mmのため尺度に乗らない。
  尺度 1:2 の寸法は 400.25/2 ではなく 400/2＋0.25＝200.25mm になる。
- グラデーションのラスタ化 DPI の既定は 150 で、75 を指定すると埋め込み PNG の画素寸法が半分になる（9画像とも非単色）。
- クリップボードは対話デスクトップの共有資源であり、登録が他アプリの操作と競合した場合は
  EMF を退避してファイル挿入を案内する失敗経路が働く（全量実行中に1件実測。退避と案内文言を確認）。

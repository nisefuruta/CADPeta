## 1. 本書が定める範囲

本書は、CAD図面をOffice文書へベクタ形式で貼り付けるツールの要求を定める。
実現方式の詳細は設計書に譲り、本書は「何を満たすか」だけを記述する。

## 2. 背景と課題

AutoCAD標準のWMFOUTおよびCOPYCLIPは、モデル空間で選択したオブジェクトのコピーに限られる。
レイアウト（ペーパー空間）で構成した図面を取得できず、プロットスタイル（CTB/STB）による色・線幅の制御も反映できない。
既存の解決策は有償の市販ツールに限られ、フリーソフトウェアとしての代替が存在しない。

以下の実現方式は、検討のうえ採用しない。いずれも本ツールの設計の前提となる。

| 棄却した方式 | 棄却理由 |
|---|---|
| Windows仮想プリンタドライバ | Microsoftがサードパーティ製プリンタドライバの縮退方針を進行中（2026〜2027年に配信停止と更新制限、Windows Protected Print Modeはサードパーティドライバを全面排除する）。長期基盤として成立しない |
| AutoCAD HDIドライバの自作 | 開発SDKが第三者に公開されていない。ネイティブC++かつAutoCAD内部ABIにバージョン単位で依存する |
| DWF（W2D）の解析 | 純正DWF Toolkitは配布終了。代替はODAの有償SDKかAGPLライセンスの実装しかなく、フリーソフトウェアの土台に据えられない |
| PDFを内部標準形式とする案 | 内部標準はSVG IR（SVGのサブセットとして定義する内部中間表現）とする。PDFはPETAの全範囲でCADの印刷結果を取得する境界形式であり、IR化後は保持しない |

## 3. 目的

利用者は、CAD図面をWord、Excel、PowerPointへ、拡大しても劣化しないベクタ図として貼り付けられる。
通常の貼付は範囲にかかわらずプロットスタイルを反映する。CADデータの文字・レイヤ・元の色を保った外部編集用SVGが必要な場合は、独立コマンド `PETADATA` を選べる。
成果物はフリーソフトウェアとして公開し、広く長く使われることを前提とする。

## 4. スコープ

### 4.1 対象

- 対象CAD：AutoCAD（本線）。互換CAD（BricsCAD、IJCAD、ARES等）は段階的に対応する
- 対象Office：Word、Excel、PowerPoint（Windowsデスクトップ版）
- 対象OS：Windows 10 / 11

### 4.2 非スコープ

- 3Dモデルの取得と変換
- ラスタ画像の高度な処理（図面に埋め込まれた画像は位置と範囲を保持して通すにとどめる）
- Windowsプリンタとしての動作（決定履歴の通り棄却済み）
- macOS / Linux対応

## 5. 機能要求

### FR-1 貼付の印刷単一経路

`PETA` はプロット処理する範囲（全体または2点窓）を必ず確定し、CADのプロットエンジンでベクタPDFを内部生成して解析する。
オブジェクト選択（先選択またはオブジェクト(O)）は範囲の代替ではなく、確定した範囲の中で出力対象を選択オブジェクトだけに絞るオプションである。
絞り込み時は、モデル空間と通常のペーパー空間図形を一時的な側DBへ複製し、元レイアウトのページ設定を引き継いで同じ範囲を印刷する。
ペーパー空間のOnである通常ビューポートを選択した場合は、元図面の一時トランザクション内で非選択のペーパー空間図形だけを非表示にし、ビューポートの尺度、視点、クリップ、画層状態、画層overrideを変えずに正規印刷する。
オブジェクト(O)はビューポート内の非表示モデル図形を強制表示しない。
一時トランザクションは印刷後に破棄し、元図面を変更しない。
CTB/STB、レイヤの印刷可否、色、線幅はCAD側の正規印刷へ委譲し、本ツールでは再実装しない。
選択された非印刷レイヤのペーパー空間の図形は、ビューポートを除き、一時側DBまたは元図面の未確定トランザクション内で退避レイヤへ移し、元レイヤの印刷条件を変えずに印刷可能にする。
尺度は絞り込みの有無に依らず範囲プロットの規則（ペーパー空間はページ設定の尺度、モデル空間は用紙合わせ）に従う。
Xref、ペーパー空間の制御ビューポート、オフのビューポート、現在空間以外の図形を除外する場合は、既定で中止し、利用者が明示承認したときだけ部分出力を行う。

### FR-2 構造SVG書き出し（PETADATA）

`PETADATA` はCAD APIから選択オブジェクトを直接取得し、構造を保持したSVGを書き出す。
オブジェクトの色がインデックスカラー（ACI）かTrueColorかを区別し、
レイヤ等の属性とともに出所メタデータとして取得・保持する。
このメタデータは診断出力とレイヤ別グループ化（FR-4）の根拠となる。

PETAの印刷PDFはこのメタデータの大半を持たない。
プロット後のPDFには最終的なRGB値しか残らず、元がACIかTrueColorかを判別できないためである。
この非対称は原理的なものであり、貼付ではなく外部編集用の `PETADATA` が存在する理由である。

**削除した要求の記録（2026-07-09）**: 本FRは当初「ACI番号ごとの線幅・塗りつぶしの指定」
「TrueColorオブジェクトの変換規則」という色による制御を含んでいたが、用途検証により削除した。
この制御はCTB/STBと同じ意味構造の再発明であり、同種の既存ツール群で中核機能となっているのは
プロットスタイルを反映できない取得方式の代替手段としてである。プロットスタイル反映済みの
印刷単一経路を持つ本ツールでは固有価値を持たない（仕上げの色変換はFR-4が担う）。再提案しない
（根拠は docs/validation/architecture-decisions.md）。

### FR-3 出力形式

ツールは、同一の内部表現から以下の形式で出力できる。

- **EMF**：Office貼り付けの主形式。クリップボード経由とファイル出力の両方を提供する
- **SVG**：長期保存と再利用の形式。Office（2016以降）への直接挿入にも使える
- **PDF**：単票の受け渡しと互換確認に使う
- **PNG**：表示互換の確認に使う

EMFは出力形式の一つであり、内部標準ではない。
将来OfficeがEMFの受け入れを制限した場合も、他の出口で継続できる構成とする。

### FR-4 整形

ツールは、取得したデータに対して以下の整形を行える。

- 背景（用紙塗りつぶし）の除去
- 図形範囲または利用者指定の任意矩形範囲（mm指定）へのクロップと余白の指定
- 線幅の正規化（最小線幅の保証を含む）
- 色変換（モノクロ化、グレースケール化、色の一括置換）
- レイヤ別グループ化（SVG出力向け。描画順が変わり見た目が崩れ得るため既定オフとし、適用時は処理ログに記録する）

### FR-5 クリップボード連携

利用者は、CAD上のコマンド一つで、整形済みのEMFをクリップボードへ載せられる。
Office側では「貼り付け」または「形式を選択して貼り付け」で受け取れる。

### FR-6 貼り付け後の寸法

EMF出力は物理寸法（mm）の情報を保持し、Officeへ貼り付けた時点で図面上の意図した大きさを再現する。
利用者が印刷尺度を指定した場合、その尺度で貼り付く。

### FR-7 CAD非依存のPDF入口

CLI/GUIの入力は、生成元を問わない任意のベクタPDFを受け付ける。
プラグイン未対応のCADで作図した図面も、そのCADがベクタPDFを出力できれば処理対象にできる。

## 6. 非機能要求

### NFR-1 ライセンスと配布

- 本体はフリーソフトウェアとして無償配布する
- 依存ライブラリは、無償配布を妨げるライセンス（AGPL等の強いコピーレフト、有償SDK）を避ける
- インストールに管理者権限とドライバ署名を要求しない

### NFR-2 対応バージョン

- AutoCAD：現行版および直近数バージョン。プラグインの実行基盤は3系（.NET Framework 4.8 = 2024以前 /
  .NET 8 = 2025・2026 / .NET 10 = 2027）で担保する（2026-07-07 確定）。対応バージョンの下限は
  プラグイン入口の実装時に確定する
- PDF入力の単独利用は、CADのインストール自体を前提としない

### NFR-3 診断可能性

不具合の原因を追跡できるよう、内部表現を中間ファイルとして書き出せる。
利用者は「取得の問題」か「変換の問題」か「出力の問題」かを、中間ファイルの確認で切り分けられる。

### NFR-4 性能

一般的な施工計画図（A3、数千〜数万エンティティ）を、実用的な待ち時間（目安として数秒以内）で処理する。

## 7. 制約と既知の限界

以下は本ツールの方式に内在する限界であり、要求として解消を求めない。
利用者への告知事項として仕様に含める。

- **透明度**：EMFはアルファ（透明度）を表現できない。透明度を含む図面は、EMF出力時に近似（背景色との合成等）へ劣化する。SVG出力は透明度を保持する
- **印刷PDFの意味情報**：プロット経由の取得では、ハッチ・ワイプアウト等がPDF段階で平坦化する。PDFのOCGがあればレイヤ名は保持できるが、意味単位での後編集は保証しない。構造編集にはPETADATAを使う
- **SHXフォント**：SHX文字はPETAでは輪郭線または特殊な埋め込みとしてPDFに載る。テキスト編集性が必要ならPETADATAを使う

## 8. 未決事項

未決事項は残っていない。確定した技術選定は次のとおり。

| 事項 | 決定 | 根拠 |
|---|---|---|
| PDF解析ライブラリ | PdfPig（C#、Apache-2.0）を本実装に採用。pypdfium2（正解レンダラ）・pikepdf（解剖）・PDFBox（正解データ生成器）を検証補助に併用 | 三段構え検証の完了。PDFBox 正解値とオブジェクト単位で全件一致（docs/validation/architecture-decisions.md） |
| EMF生成方式 | クラシックGDIレコードの直書き（P/Invoke）。EMF+ は不採用 | 分解編集・文字編集・寸法精度・サイズの全観点で優位（docs/validation/architecture-decisions.md §5） |
| 実装言語 | C#（.NET） | CADプラグイン、PDF解析、SVG IR実装を共有できるため |
# GUI版（PDF入力）

- CADを所有しない利用者が、ベクタPDFをドラッグ＆ドロップして色変換、背景除去、クロップ、文字輪郭化、
  レイヤ別グループ化を指定できること。
- 変換結果をプレビューし、EMFとしてOfficeのクリップボードへ登録、またはEMF/SVG/PDF/PNGへ単一・複数保存
  できること。通常利用の意味論はCLIと共通化すること。
- GUIはWindows 11/.NET 10 Desktop Runtime x64向けのframework-dependent単一実行ファイルとし、CADを要求しないこと。
- 段階SVGダンプ（`--diag`）は開発者向けCLI専用とし、GUIでは診断サマリを表示すること。
